# AR 解球可行性与最小原型方案

研究日期：2026-10-12。状态：方案与代码边界审查完成；没有真实球台素材、真机性能或识别精度结果，不能据此宣布 AR 已验证可用。

## 结论与范围

建议先验证“固定手机、静止球局、拍照冻结、人工确认球台和球位、叠加一库路线”的最小闭环。通过离线几何与真机误差门槛后，再增加自动识别和移动相机跟踪。首期采用 CameraX + OpenCV 的平面视觉方案，不需要 ARCore；平面追踪本身不能识别库边、球位和球号。

当前主项目是根目录的原生 Android Java 应用：AGP 8.7.3、compile/target SDK 35、min SDK 23；MainActivity 继承 Activity，PracticeView 的 AR 按钮仅显示未接入提示，Manifest 尚无相机权限。`lianxi-1.0.0` 是另一个 Flutter 工程，不能混为当前 Android 构建入口。

本次只新增本文档。后续原型建议放在独立 `experiments/ar-prototype` 工程、使用独立包名；不要先改主项目的构建、Manifest、按钮或物理参数。最终集成由总控决定。

## 分阶段闭环

| 阶段 | 实现与输出 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 离线几何 | 导入照片，选四条库鼻直线并求虚拟交点，输入实测台面尺寸，生成俯视图和回投影网格；人工标注球位 | 留出校验点误差达标；旋转、裁剪、畸变映射正确 |
| P1 冻结画面 | 独立 APK 打开后摄，冻结同一分析帧，识别球台候选、球候选；用户修正并指定母球、目标球和方向；叠加一库路线 | 真机可完成完整操作，球位误差达标，拒绝权限及退出正常 |
| P2 固定机位实时 | 预览与分析解耦、球局稳定检测、库边重检测、过期结果隐藏 | 长时间延迟、抖动、温升与跟踪失效处理达标 |
| P3 可选移动机位 | 每帧可靠地更新外参/单应性，比较标记辅助和自然特征跟踪 | 有独立移动机位测试结果才允许称为实时 AR |

P0/P1 必须同时展示原图、校正网格、候选球和置信状态。用户确认后输出不可变场景快照，不直接覆盖自由练习球局。球号识别、自动球杆检测、运动球跟踪、旋转和多库精确预测均不属于第一轮验证。

## 数据链与几何约定

1. **相机帧**：记录 frameId、时间戳、cameraId、分辨率、rotationDegrees、cropRect、缩放倍率和标定编号。读取 YUV 时处理 rowStride/pixelStride，禁止假定是连续 NV21。冻结的底图必须来自同一分析帧。
2. **球台候选**：台呢颜色分割 + 边缘/直线拟合，寻找四条库鼻线；口袋使四角不完整，应求库鼻延长线交点，不把木框外沿或袋口当成台面角。保留人工选四线/四点和修正入口。颜色阈值只作为候选生成器，不能硬编码“绿色就是球台”。
3. **标定**：坐标采用实测毫米，原点为约定的左上库鼻虚拟交点，x 向长边、y 向短边。四点按 TL/TR/BR/BL 对应 `(0,0),(L,0),(L,W),(0,W)`，检查凸性、面积、顺序、共线退化。四点可求 H；多于四个可靠对应点可用 RANSAC。四个拟合点的低重投影误差不代表泛化准确，必须用未参与拟合的内部标记检查。
4. **球检测**：在台面 ROI 中组合颜色差、轮廓和局部边缘；远端球较小，必须按透视尺度筛候选。圆/椭圆拟合仅是检测辅助；反光、阴影、贴库球、粘连球均需不确定标记。MVP 只分母球候选和其他球，由用户确认身份，不需要自动读球号。[OpenCV 轮廓接口](https://docs.opencv.org/4.x/d3/dc0/group__imgproc__shape.html)
5. **球位校正**：H 只适用于台面，球体轮廓中心不在台面上。先保留“直接映射中心”的误差基线，再使用内参、畸变、已知球半径和 solvePnP 求位姿，拟合球体投影或验证中心射线与 z=r 平面求交近似。椭圆中心也未必等于三维球心投影。低机位误差不达标时，限制机位或保留人工修正，不能用平滑掩盖系统偏差。[平面单应性与位姿](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)
6. **路线**：使用独立参数化纯几何计算，输入实测 L/W/r、球位、瞄准方向、库边有效区间。球心碰库边界为 `r..L-r` / `r..W-r`；球球接触判定用 2r。先支持一库理想镜面反射，遇球停止；遇袋口或袋角附近停止并标记不可预测，不跨袋口画连续库边。
7. **回投影**：约定 H 为“去畸变图像 → 台面”。台面轨迹通过 H⁻¹ 得到去畸变像素，再按需要重新施加镜头畸变，最后做分析帧到 PreviewView 的旋转/裁剪/缩放。若底图本身已经去畸变则不重复施加畸变。存在畸变时采样线段后逐点投影，不只连接端点。屏幕触点按相反链路转换。[CameraX 坐标变换](https://developer.android.com/media/camera/camerax/transform-output)

路线默认表示台面上的球心轨迹投影，球标记单独按球体几何绘制，避免把 z=0 的线误解释为穿过可见球心的 z=r 空间线。

当前 PracticePhysics 使用 WIDTH=2、HEIGHT=1、R=.022；Flutter 参考工程也使用放大的显示球半径及图像库边偏移。这些都是练习模型参数，不能直接充当实测球台标定。只借鉴接口或算法，待参数化并单独验证后再谈复用。

## 依赖与隔离

| 依赖 | 用途 | 验证要求 |
| --- | --- | --- |
| AndroidX CameraX core/camera2/lifecycle/view | 后摄预览与 ImageAnalysis | 选择兼容当前 SDK/AGP 的同版本稳定组件，锁定版本；本次未解析依赖或验证构建 |
| AndroidX lifecycle / ComponentActivity | 原型生命周期 | 原型独立使用，不为了相机直接替换主 MainActivity 基类 |
| OpenCV Android SDK（Java 接口、原生库） | 标定、轮廓、单应性与投影 | 锁定具体版本、来源与许可证；验证 arm64-v8a、原生库加载、16 KB 页设备兼容及 APK 增量 |
| Python + OpenCV + NumPy（离线可选） | 素材回放、误差统计 | 固定环境版本，保存配置和随机种子；不进入主 APK |
| CAMERA 权限 | 原型拍摄 | 只在原型入口申请；拒绝、永久拒绝、后台/恢复和相机占用均可退出或重试 |

第一轮不增加训练模型、云推理、ARCore、录音权限或广泛存储权限。素材默认本地分析，由明确的导出操作保存。只有传统视觉基线在留出数据集失败后，才评估检测模型的数据量、端侧时延与许可证。

标定使用同镜头、同分辨率/裁剪和固定缩放；镜头切换、数字变焦、预览裁剪变化均令旧映射失效。棋盘格/ChArUco 的实际格长必须测量，覆盖画面中心与边缘、多角度采集，记录独立验证误差。[OpenCV 相机标定](https://docs.opencv.org/4.x/d4/d94/tutorial_camera_calibration.html)

## 性能预算与失效行为

以下为拟定验收目标，全部尚未实测；必须记录实际设备型号、SoC、系统、镜头和温度条件。

| 项目 | 初始目标 / 约束 |
| --- | --- |
| 预览 / 分析 | 预览目标 30 fps；分析 5–10 Hz，先试 1280×720，再按远端球尺寸选分辨率 |
| 可识别尺度 | 远端完整球直径暂定至少 16 px；低于阈值提示靠近/调整机位，不凭上采样声称提升精度 |
| 分析耗时 | 每帧 p95 ≤100 ms；单工作线程、最多一帧在处理，不建立待分析队列 |
| 端到端时延 | 用图像时间戳到可见叠加测量，p95 ≤200 ms；结果年龄 >250 ms 隐藏实时路线 |
| 内存 | 原型总 PSS 暂定 ≤200 MB；复用 Mat/缓冲，不逐帧分配 Bitmap；15 分钟后无持续增长 |
| 持续运行 | 15 分钟后分析频率仍 ≥5 Hz，时延满足目标；记录降频和温升，不把首分钟数据当持续性能 |

CameraX 使用 KEEP_ONLY_LATEST；分析线程在 finally 中关闭 ImageProxy，退出时解绑并释放 executor/Mat；不能关闭其内部 Media.Image。预览与分析帧率分开统计。[CameraX 图像分析](https://developer.android.com/media/camera/camerax/analyze)

静止检测需连续多帧、结合跟踪点位移和球位变化；禁止球运动时输出静态解球结果。相机移动、遮挡、四边失效、角点漂移、校准失效时隐藏路线并要求重新确认。P1 冻结照片模式明确显示“冻结画面”，不能把旧画面的路线覆盖到新实时预览。

## 测试素材与标注

最低首轮素材包：3 台实机（低/中/高性能，含目标用户手机）、2 张不同台呢/照明的真实球台，每个设备×球台组合采集 20 张原图，共 120 张；每组合 4 段 20–30 秒视频，共 24 段。另采每个镜头配置约 20 张不同姿态标定板图，数量以标定覆盖度和独立误差决定。

照片覆盖：高/中/低机位、近远端、空台、1/3/16 球、白球/条纹白区域、黑球、贴库、贴袋、粘连、部分遮挡、强反光、阴影、低照、蓝/绿台呢；可交叉覆盖，不宣称覆盖全部组合。视频覆盖固定机位、慢移/快移、遮挡恢复、击球运动，保留时间戳与原始分辨率，不用聊天软件压缩图替代原始素材。

标注记录 imageId/sessionId/deviceId/tableId、内参版本、四条库鼻线/虚拟角点、实测 L/W/r、每球可见轮廓及遮挡状态、母球身份、台面实际球位、校验点、光照/角度、预期失败原因。球位真值应通过定位模板/实测参考网格取得，移走模板后拍摄且不移动球；不能把待测算法的输出或同一照片人工轮廓中心当毫米真值。

素材按采集 session/球台划分开发与留出测试，至少保留一张球台的完整会话；同一视频相邻帧不得分到两侧。按角度、设备和困难类型分别统计，报告样本数，不能只报全局均值。

## 验收与交付门槛

- 几何：合成点往返误差 <0.1 px；不同旋转/裁剪变换均通过。真实台面留出点误差 p95 ≤5 mm；四点共线、顺序错误和不可逆 H 明确拒绝。
- 检测：在定义的支持条件内，未遮挡可见球的 precision/recall 均 ≥95%；报告人工修正比例及母球误判率。遮挡/小球单列，不能静默剔除。
- 球位：独立实测球心平面位置误差 p95 ≤10 mm；分别比较有/无高度校正。达不到则仅保留人工确认的冻结画面模式，不能宣传精确解球。
- 叠加：在规定 1280×720 基准画面内，独立台面标记回投影误差 p95 ≤4 px；固定机位 10 秒静态点抖动 p95 ≤3 px。定义为相对时间中位位置的距离，并同时报告毫米值及分辨率。
- 路线：已知坐标的正碰、斜碰、擦球、贴库、袋口和一库路径通过纯几何用例；单独记录真实一库试球偏差，不能把几何测试通过当作真实物理预测通过。
- 失效：拒绝权限、切后台恢复、锁屏、相机占用、快速移动、镜头/缩放变化和过期结果都有清楚行为，不崩溃、不显示仍有效的旧路线。

交付应包括：独立原型 APK/源码与依赖锁定信息、原始/校正/叠加示例图、素材清单与标注、逐帧耗时 CSV、分组误差统计、失败案例和支持机位说明。达到 P1 后才由总控评审是否接入实验入口；P2/P3 各自单独验收，不以存在相机预览替代 AR 验证。

目前缺口：尚未采集上述真实素材、未构建 CameraX/OpenCV 原型、未测真机性能和几何误差。现有模拟器练习功能测试不能填补这些缺口。
