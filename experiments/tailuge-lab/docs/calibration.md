# 实台标定记录

`src/calibration.ts` 的 `initialChineseEightBallProfile` 是中式八球 9 尺工程初值，**不是已标定值**。它使用 2.54 × 1.27 m 台面、半径 28.575 mm / 质量 0.17 kg 球；滚动摩擦、滑动摩擦、旋转衰减、库边系数和袋口比例仍是 Tailuge 模型的可替换起点。

`joyCompetitionInitialProfile` 是用户提供的“乔氏/赛事级中八初始档案”，同样不是某张实体台的已标定结果。它记录赛事台高密羊毛呢、进口高弹库胶 / 65 锰钢复合，以及库边回弹相对误差目标小于 1%。它将三种袋口定义分别存档：口沿约 **85 mm**、角袋内沿最短可通过宽度 **105 mm ±1 mm**、腰袋可通过宽度约 **120 mm**。这些读数不可互换，也不应折算成同一个“袋口半径”。

当前 Tailuge 简化袋口只提供一个全局 `openingScale` 和 `jawScale`；这两个运行时参数不能分别表达口沿、角袋最短通道和腰袋通道。因此赛事档案暂保持两层数据：原始三类测量完整存于 `pockets.measurements`，统一缩放仍为 `1`。要真正使用 85 / 105 / 120 mm，需要替换或扩展 `PocketGeometry`：为角袋与腰袋分别定义口沿直线、两侧 jaw 坐标/半径、袋喉通道与袋心，再用每类“刚好进 / 刚好不进”边界球拟合；完成前不得声称这些物理尺寸已进入运行模型。

每次实台标定建立一个新的 JSON profile，保留 `id`、台号、日期、视频文件和原始测量值。不要覆盖初值；让题库记录它所使用的 profile `id`。

## 录制与读数

1. 用卷尺量两条库边之间的有效台面长度和宽度，单位为 m；同一张表记录球直径、称得的球重和袋口宽度。相机应正上方固定，画面包含全部台面；用四个内角做透视校正，让像素坐标映射至 m。
2. 以至少 120 fps 拍摄，240 fps 更适合球球碰撞。开拍前在台呢上放一把已知长度直尺，或记录内库边尺寸，作为比例尺。逐帧读球心，不要读球边缘；记录每次误差估计和遮挡帧。
3. 按 `calibration-measurement-template.csv` 的六行各打 5–10 次。发力方式必须可复现：最好使用可读速度的出杆装置；手工出杆时只把速度相近的重复组放入同一拟合批次。
4. 直线滑行用停球中心到起点的距离拟合 `cloth.rollingFriction`；以滑动转滚前的减速段拟合 `cloth.slidingFriction`；原地侧旋衰减用于 `cloth.spinDecay`。
5. 正碰、薄碰用碰撞后两球球心轨迹和速度校验碰撞模型；一库用入射和出射角、首次接触点及速度拟合 `cushion.restitution`、`tableFriction`、`cushionFriction`。先固定台呢参数，再调库边。
6. 中袋和底袋记录“刚好进 / 刚好不进”的瞄准线和入射速度。以这两组边界调 `pockets.openingScale`、`pockets.jawScale`。调袋口后必须重跑一库和薄碰，避免用错误袋角掩盖库边问题。

每一次只调整一个参数族，保存 profile JSON 并运行全部标定场景。接受 profile 前应比较实测与模拟的距离、角度、首次库边接触位置和入袋边界；不要只凭“看起来相似”接受。

## 运行校验

```powershell
pnpm run build
pnpm test
```

`calibrationScenarios` 包含五类检查：直线滑行、正碰、薄碰、一库，以及含中心袋和底袋两条基准的入袋类。它们验证模型链路和 profile 注入的可重复性，不代表已与任何实体球台吻合。
